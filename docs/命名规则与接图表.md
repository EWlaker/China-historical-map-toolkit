# 命名规则与接图表

这两件事是配套的：

- **命名规则**决定每幅图怎么被定位 —— 从文件名解析出图号，再换算成经纬度
- **接图表**是校验这套规则对不对的**唯一权威依据**

它们都遵循同一条规律：**错了不会报错**。文件名里的编号差一位，图就被安静地放到隔壁去了，程序照常跑完，产物看起来完全正常。

---

## 一、文件命名规则

### 1.1 最小要求

```
<图号>-<图名>.jpg
```

- **图号**：必须能从中解析出"列号 C"和"行号 R"
- **图名**：任意文字，用于人工识别、报告可读性、文件名排序

分隔符、位数、顺序都可以不同，只要 `filename_regex` 能匹配上。

### 1.2 内置规则：CCRR

民国五万分之一地形图常见的一种编排 —— 前两位列号、后两位行号：

```
2108-瑪瑙觀.jpg
││││
││└┴─ 行号 R = 08
└┴─── 列号 C = 21
```

```
west  = origin_lon - step_lon × C
south = origin_lat - step_lat × R
```

```yaml
grid:
  rule: CCRR
  ccrr:
    origin_lon: 116.25         # C=0 时的西边界
    step_lon:   0.25           # 每列 15′
    origin_lat: 33.333333333   # R=0 时的南边界
    step_lat:   0.166666667    # 每行 10′
```

**注意**：`C` 越大越靠西（列号自东向西递增）。这与直觉相反，但在民国图集里是常见做法，务必以接图表为准。

### 1.3 适配其他编号体系

分三种情况处理：

**情况 A：同样是"列+行"，但位数/顺序/分隔符不同**

只改正则即可：

```yaml
grid:
  # 形如 "C21-R08-瑪瑙觀.jpg"
  filename_regex: '^C(?P<c>\d+)-R(?P<r>\d+)-(?P<name>.+?)\.(?:jpg|jpeg|png|tif|tiff)$'
```

正则里必须包含命名组 `c`（列号）、`r`（行号）、`name`（图名）。

**情况 B：图号与经纬度是另一套线性关系**

改 `origin` / `step` 四个值。例如图廓是经差 30′、纬差 20′：

```yaml
grid:
  ccrr:
    step_lon: 0.5
    step_lat: 0.333333333
```

`origin` 需要从接图表上实测——**取某一格，读它的图号，再读它图廓标注的经纬度，反解出 origin**。

**情况 C：图号与经纬度没有解析关系**（纯流水号、按页序编号）

这种情况不能用这套自动换算，两条出路：

1. **逐幅指定**：`grid.overrides` 手工填每一幅的 `[C, R]`
2. **改用控制点配准**：找古今对照点做几何纠正（属于另一个课题，本工具包不做）

### 1.4 逐幅修正

当扫描件的编号与图集接图表不符时：

```yaml
grid:
  overrides:
    "0122-龍湖": [1, 21]      # 文件名是 22, 实际在第 21 行
```

**这类错位往往成对出现。** 实际遇到过：两幅图的编号都比实际位置大 1，于是整体向上错了一格。发现一幅后，**建议顺带检查它上下左右相邻的几幅** —— 要么是孤立错误，要么是成片偏移，两者处理方式不同。

## 二、接图表

### 2.1 它是什么

图集的总图（索引图）。上面按行列画出所有图幅的格子，**每格标注该幅的图号和图名**。

它通常藏在图集的第一页，或者扫描件里那个"不该被当成地图处理"的文件。**开工前一定要先把它找出来，并加进 `crop.exclude`。**

### 2.2 三个用途

#### 用途一：核对图号换算规则（最重要的第一步）

**在跑任何批量之前做这件事。**

1. 从接图表上挑 2~3 格，记下它们的图号
2. 按配置里的公式算出经纬度矩形
3. 打开对应的原图，读它**图廓（边框）上的经纬度注记**
4. 对比

以图号 `2108`、默认配置为例：

| 项 | 算出 | 图廓注记应为 |
|---|---|---|
| 西边界 | 116.25 − 0.25×21 = **111.00°** | — |
| 东边界 | 111.00 + 0.25 = **111.25°** | `111°15′` |
| 北边界 | 33.333333 − 8/6 + 1/6 = **32.1667°** | `32°10′` |

(32.1667° = 32°10′)

**对不上就先改配置，不要开跑。** 猜错了整批数据都会错位。

#### 用途二：发现缺幅

接图表上有的格子，我们手上却没有这一幅。

**实战案例**：接图表上 `C=21 R=8` 清清楚楚写着 `2108 瑪瑙觀`，而清单里 C=21 列的 R=8~13 整段是空的，全库也搜不到"瑪瑙觀"这个名字。后来使用者从别处找到了这一幅，补进来，全库从 396 幅变成 397 幅。

**判断方法**：接图表上该格**有图号和图名**，而清单里没有对应记录。

#### 用途三：发现错位

接图表上该格的图号，与文件名里的编号不符。

**实战案例**：接图表上读到的序列是

```
R=19:  0319桐樟河 | 0219亭前驛 | 0119花凉亭
R=20:  0320廣濟縣 | 0220黃梅縣 | 0120宿松縣
R=21:  0321龍坪   | 0221孔攏鎮 | 0121 湖龍   ← 龍湖
R=22:  0322赤湖   | 0222九江縣 | 0122 縣口湖 ← 湖口縣
```

而扫描件的文件名是 `0122-龍湖`、`0123-湖口縣` —— **编号整体比接图表多 1**，导致两幅图向南错了一格。

修正后 C=1 列变成 R=19/20/21/22 连续四格，与相邻列排成一个规整矩形；不修正的话，`0123-湖口縣` 会孤零零挂在 R=23，而 C=2、C=3 两列在 R=23 根本没有图幅。

**一个有用的旁证**：修正后各列的行号应当是**连续的**。如果某列中间空一格、或某幅图孤悬在外，就值得怀疑。

### 2.3 程序辅助核对的正确姿势

接图表上有图的格子写了图号，没图的格子是空白 —— 所以可以**用墨迹密度自动判断"哪里真的有图"**，再与清单对比。

思路：

1. 把接图表按网格切成格子
2. 统计每格中心区域的墨迹占比
3. 墨迹高的判为"有图"，与清单做集合对比
4. 找出两类异常：清单有图但接图表空白、接图表有图但清单没有

**但必须目视复核 —— 误报极多。** 实际遇到的误报来源：

| 程序报警 | 真实原因 |
|---|---|
| 墨迹 30.6% | 是"河南省/陝西省"的省界标注 |
| 墨迹 17.4% | 是图框内的说明文字（如"全省共約五百一十幅"） |
| 墨迹 14.5% | 是一条河流线 |
| 墨迹 7.2% | 实际有图名，只是字迹偏淡 |

**自动筛查的价值在于缩小需要看的范围，不在于给出结论。**

### 2.4 网格标定的坑

要用程序切格子，就必须先知道网格在哪。**不要假设网格均匀铺满图框** —— 实测这么假设会整体偏掉**整整一列（约 60 像素）**，因为图框内还有行号栏和说明文字占地方。

正确做法：**找一行图幅排满的位置，实测竖线的真实间距**。

判别效果的差距很大：

| 网格参数 | 列宽 | 判别分离度 |
|---|---|---|
| 均匀假设 | 65.97 | 9.4 |
| 实测标定 | 63.00 | **20.6** |

**扫描件的几何参数一律要实测，不要从"设计值"推。**

## 三、上手顺序

```
1. 找到接图表，加进 crop.exclude
        ↓
2. 从接图表挑 2~3 格，核对图号换算规则
        ↓
3. 与原图图廓的经纬度注记对比 —— 对不上就改配置
        ↓
4. 单幅试跑，确认裁切与配准都正常
        ↓
5. 全量跑
        ↓
6. 用接图表抽查：各列行号是否连续？有没有孤悬的图幅？
        ↓
7. 有疑问的格子逐格目视，不要只信程序
```

## 四、常见问题

**Q: 扫描件编号和接图表不一致，以哪个为准？**

**以接图表为准。** 它是图集编制时统一编排的，而扫描件的文件名往往是后来人工录入的，容易出错。

**Q: 接图表某格空白，但清单里有这一幅。**

两种可能，必须目视确认那格到底是不是空白：

1. 这幅图确实存在，接图表漏画了（补测图、后印图）
2. 编号错了，它实际在别的格子

**Q: 接图表上有的图幅，我手上没有。**

正常。民国图集散失很常见。用接图表统计总数，能知道缺了多少 —— 例如接图表标注"全省共約五百一十幅"，而手上只有 397 幅。

**Q: 文件名里的图名和接图表上的不一致。**

图名以**原图图廓上印的**为准。接图表是手写或早期印刷的，形近字讹误不少（如"篠/條"、"栗/票"、"六/大"）。

**Q: 能不能干脆不管编号，直接按页序排？**

那样只能得到"拼在一起"的效果，得不到**地理坐标**。而没有坐标就无法与卫星影像、现代地图叠加分析 —— 这正是本工具包与外行拼接方案的区别所在。
