# 参数调优

## 一、先看诊断，再改参数

不要凭感觉调。先跑一遍，然后看 `work/01_crop/crop_report.json`：

```json
{
  "file": "2108-甲幅",
  "status": "ok",
  "angle": -0.66,
  "outer": [67, 67, 1866, 1406],
  "inner": [102, 102, 1898, 1438],
  "ratios": [0.997, 0.982],
  "flag": "ok"
}
```

各字段含义：

| 字段 | 含义 | 异常信号 |
|---|---|---|
| `angle` | 检出的倾斜角 | 接近 ±3°（搜索边界）说明图歪得厉害，可能解错 |
| `outer` | 外框图廓 (x, y, w, h) | w 或 h 特别小 → 细条误检 |
| `inner` | 最终裁切范围 | 与 outer 差异过大 → 内容框不可信 |
| `ratios` | [宽比, 高比] 内容框/外框 | 远小于 1 → 边缘被当空白切掉 |
| `flag` | `ok` / `safe` | `safe` 表示走了保守兜底 |

**`safe` 不是错误。** 它是设计好的保守路径：不确定时整幅保留，
代价是留白，收益是绝不切内容。只有当你确认那幅图本来边缘就没内容时，
`safe` 才是多余的。

## 二、逐参数说明

### `crop.density_threshold`（默认 0.10）

判定"这一行/列有内容"的墨迹占比门槛。

**取证方法**：拿几幅典型图，统计它们的边缘区域墨迹占比。

| 图幅类型 | 边缘墨迹占比 | 用 0.10 | 用 0.15 |
|---|---|---|---|
| 内容密集（城市、山区） | 0.28~0.87 | 正常 | 正常 |
| 内容稀疏（湖区、平原） | 0.08 左右 | 正常 | **切掉边缘** |

这就是为什么默认取 0.10：它照顾稀疏图幅。
密集图幅留白多一点点，但不会出错。

**调参方向**：
- 发现边缘被切 → **调小**（0.10 → 0.08）
- 发现留白太多且确认边缘无内容 → **调大**（0.10 → 0.13）

### `crop.density_window`（默认 20）

要求连续多少个像素超过阈值才算边界。

它的作用是**抗噪**：一道折痕、一个污点不会形成 20px 的连续游程。
如果你的扫描件很干净，调小（10）能让边界更贴合；
如果噪声大（老旧复印），调大（30）更稳。

### `crop.safe_ratio`（默认 0.72）

内容框小于外框的这个比例时，判定检测结果不可信，整幅保留。

**为什么是 0.72**：正常图幅的内容框通常占外框的 0.9 以上
（实测密疏两类分别是 0.96~0.997 和 0.93 左右）。
真出现 0.72 以下，多半是检测出了问题而不是图真的只有那么大。

**调参方向**：想更激进地贴边裁 → 调到 0.6；
想更保守 → 调到 0.85。

> ⚠ 调小这个值意味着**承担切内容的风险**。除非你能逐幅复核，否则别动。

### `crop.force_safe`（默认空）

逐幅强制走保守路径的名单。**发现某幅被切了内容，第一反应就是把它加进来**：

```yaml
crop:
  force_safe: ["0217-桐山", "1506-湖陽鎮"]
```

同时把这幅记录下来——这些"检测失败样本"是调参最有价值的输入，
比随机抽十幅看都有用。

### `crop.outer_band`（默认 0.025）

排除图廓线本身所占的边带比例。

图廓是粗黑线，如果不排除，它自己就会被当成"内容"，
导致裁切范围永远等于整个外框。

一般不用改。如果图廓特别粗（比如占短边的 5%），可以调到 0.04。

### `georef.east_shift_m`（默认 0）

整体东移，用于对齐现代底图。

$$\Delta\text{lon} = \frac{\text{shift}_m}{111320 \cdot \cos(\varphi)}$$

> ⚠ **这个量依赖中心纬度。** 如果你移动了图幅（比如发现编号错位、
> 把某幅整体挪了一格），纬度就变了，**必须按新纬度重算**。
> 否则矢量图框与栅格影像会在东西方向悄悄错开。
> 实测一个图幅的纬度变化会造成约 10 米（0.0001°）的错位——
> 单看没事，GIS 里放大叠加就露出来了。

### `grid.ccrr.*`（图号换算）

```
west  = origin_lon - step_lon × C
south = origin_lat - step_lat × R
```

默认值对应图廓经差 15′、纬差 10′，即：

- `step_lon = 0.25`（15′ = 0.25°）
- `step_lat = 0.166666667`（10′ = 1/6°）

**必须实测验证**。方法：打开一幅原图，读它图廓右上角的经纬度注记，
和公式算出来的比。对不上就说明规则不对。

### `grid.overrides`（逐幅位置修正）

扫描件编号与图集接图表不符时用：

```yaml
grid:
  overrides:
    "0122-龍湖": [1, 21]
```

**这类错位常常成对出现。** 实际遇到过的情况是：两幅图的编号
都比它们的实际位置大 1，于是整体向上错了一格。
发现一幅后，建议顺带查它上下左右相邻的几幅——
要么是孤立错误，要么是整片偏移，两种情况处理方式不同。

判断依据应当以**图集接图表**为准（那上面逐格标了图号），
而不是靠地名去猜。

## 三、调参工作流

```
1. 跑全量
      ↓
2. 看 crop_report.json
      ↓
3. 按 flag / ratios 筛出可疑图幅
      ↓
4. 打开可疑图幅的成果肉眼确认
      ↓
5. 分类：
     ├─ 切了内容   → 加进 force_safe，记录样本
     ├─ 留白过多   → 记下来，看是否成片出现
     └─ 正常       → 忽略
      ↓
6. 只有当一个参数能解决"成片出现"的问题时，才去改它
      ↓
7. 改完先单幅试跑，再考虑全量
```

**不要为单个图幅改全局参数。** 用 `force_safe` 单独处理它。
全局参数一改，几百幅的结果全变，可能修好一幅弄坏十幅。

## 四、验收清单

跑完批量后逐项确认：

- [ ] `python scripts/tools/check_outputs.py` 全部通过
- [ ] 裁切成果尺寸完全一致（由 `out_size` 决定）
- [ ] `crop_report.json` 里 `status: fail` 的数量是 0
- [ ] `flag: safe` 的图幅逐幅看过，确认留白可接受
- [ ] 随机抽 5~10 幅在 GIS 里打开，坐标范围与图廓注记对得上
- [ ] `mosaic.vrt` 拖进 QGIS，图幅之间**没有重叠、位置关系正确**
- [ ] 图幅总数 = 输入目录图片数 − `exclude` 里的数量

> 最后一条特别容易漏。如果数字对不上，多半是输入目录里混进了
> 接图表、封面之类的非图幅文件。
