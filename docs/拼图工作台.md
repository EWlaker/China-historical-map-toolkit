# 拼图工作台 —— 用拖拽确定图幅位置关系

## 它解决什么问题

有些扫描件**没有图号、没有接图表、图上也没有经纬度**。这种图：

- 算不出坐标（没有图号 → 没有换算规则）
- 也没法自动排布（不知道谁挨着谁）
- 但它们本来**就是一张整图切开的** —— 人一眼就能看出哪两幅相邻

**缺的只是一个把人的判断记录下来的工具。**

拼图工作台就是干这个：把裁好的图做成缩略图，你像拼拼图一样拖到正确位置，
它输出一份位置关系（JSON），再据此拼成整幅。

---

## 两步走

### 第一步：生成拼图界面

```bash
python scripts/tools/make_puzzle.py
```

它会读取 `work/01_crop/` 里的裁切成果，生成 `puzzle.html`：

```
读取 14 幅缩略图（宽 260 px）...
   14/14

拼图工作台已生成: puzzle.html  (0.25 MB)
```

**这个 HTML 是自包含的** —— 缩略图以 base64 内嵌，拷到任何机器、断网都能打开，
不需要装任何东西。

加 `--open` 可以直接打开浏览器：

```bash
python scripts/tools/make_puzzle.py --open
```

### 第二步：拖拽排列

浏览器打开 `puzzle.html`：

```
┌──────────────────────────────────────────────────────┐
│  拼图工作台          已放置 0/14   [自动排布][全部取回][导出布局] │
├──────────┬───────────────────────────────────────────┤
│ 待放置(14)│                                          │
│  ┌────┐  │       画布（拖到这里，自动吸附格子）        │
│  │缩略│  │     ┌────┬────┬────┐                     │
│  └────┘  │     │    │    │    │                     │
│  ┌────┐  │     ├────┼────┼────┤                     │
│  │缩略│  │     │    │    │    │                     │
│  └────┘  │     └────┴────┴────┘                     │
└──────────┴───────────────────────────────────────────┘
```

**操作：**

| 动作 | 效果 |
|---|---|
| 从左栏拖到画布 | 放到那一格 |
| 拖动已放置的图块 | 换位置（原格自动空出） |
| **双击图块** | 退回左栏 |
| 点「自动排布」 | 先按顺序铺一遍，再手动调 —— **推荐这么起步** |
| 点「导出布局」 | 弹出结果 + JSON |

**画布是无限网格**，往右下拖会自动扩展。

### 第三步：导出并拼接

点「导出布局」后，弹窗里有两样东西：

1. **一张表**：哪幅图在第几行第几列
2. **一段 JSON**：存成 `puzzle_layout.json`

然后：

```bash
python scripts/tools/assemble_by_layout.py puzzle_layout.json
```

```
布局: 14 幅  4 列 x 4 行
输出尺寸: 18000 x 14000 像素  (252 百万像素, 彩色)
  预计文件大小: 约 1008 MB (PNG 无损)
  [!] 超过 1.5 亿像素。建议加 -s 0.5 缩小，或用 --jpg 输出
  已摆放 14/14

拼好了: work/03_assembly/assembled.png
  14 幅  18000x14000像素  彩色  354.9 MB
```

## ⚠ 拼接的产物很大，先想清楚要什么

14 幅 4500×3500 拼成 4×4 就是 **2.5 亿像素**。原尺寸 PNG 能到 350 MB ~ 1 GB。

**先按用途选参数：**

| 你要什么 | 命令 | 结果 |
|---|---|---|
| 只是看看拼得对不对 | `-s 0.3 --jpg` | 几 MB，够看 |
| 屏幕浏览 / PPT | `-s 0.4 --jpg` | 约 9 MB |
| 打印 | `-s 0.6 --jpg` 或原尺寸 | 几十 ~ 几百 MB |
| 长期存档 | 原尺寸 `--jpg` | 无损不必用 PNG，JPEG q92 足够 |

```bash
# 推荐先用这个快速验证位置对不对
python scripts/tools/assemble_by_layout.py puzzle_layout.json -s 0.3 --jpg

# 确认无误再出正式版
python scripts/tools/assemble_by_layout.py puzzle_layout.json -s 0.6 --jpg
```

**工具会先报出尺寸和预计体积再动手**，觉得太大就 Ctrl+C。

加 `--report` 会额外导出一份 CSV，记录每幅在整图中的像素坐标：

```csv
row,col,x_px,y_px,width,height,name,label
1,1,0,0,4500,3500,F_004028_xxx_inner.png,F_004028_xxx
1,2,4500,0,4500,3500,F_004030_xxx_inner.png,F_004030_xxx
```

这个 CSV 有用 —— 如果你想在别处（比如 Python 脚本、QGIS）继续处理，
它就是"哪幅图该贴在哪"的完整依据。

## 这个产物的边界

**能得到：**

- 一张真正连在一起的整图（位置关系由你判断，不是机器猜的）
- 颜色完整保留（如果原图是彩色）
- 一份可复用的位置关系 JSON / CSV
- **接图表的雏形** —— 虽然没有图号，但"谁挨着谁"这件事已经记录下来了

**得不到：**

- **没有地理坐标** —— 它是图片，不能与卫星影像叠加
- **不能量算距离、面积**
- 相邻图幅之间靠人工判断，**接缝处可能有重影或错位**（原图切分与扫描误差）

**要真实坐标，必须走配准那条路**（需要图号或接图表）：
见 [命名规则与接图表.md](命名规则与接图表.md)。

---

## 什么时候该用它

| 你的情况 | 该用什么 |
|---|---|
| 有图号，能算经纬度 | 配准流程（01 → 02 → 03），**不需要拼图** |
| 有接图表，能对照查位置 | 按接图表定图号，再走配准 |
| **什么都没有，但图是一套连续的** | **拼图工作台** ← 就是这里 |
| 只有一两幅，也不相邻 | 拼图也没意义，单幅看就行 |

## 常见问题

**Q: 拖错了格子怎么办？**

直接拖到新格子，原来的自动空出。**双击**可以退回左栏。

**Q: 我不知道该从哪幅开始排。**

先点「自动排布」按顺序铺满，然后对着缩略图逐个挪到正确位置。
比从空白画布开始快得多。

**Q: 导出后发现有幅图放错位置了。**

回浏览器改完重新导出即可，**不用重跑裁切**。拼图这一步是纯几何摆放，
随时可以重来。

**Q: 能自动判断哪两幅相邻吗？**

目前不能。理论上可以算**边缘像素相似度**来推荐候选邻居（相邻图幅在接缝处的
线条应当延续），但那需要额外的算法验证，暂未实现。

**现在的设计取向是：机器不猜，人来定，机器只负责记录和执行。**
这样即使推荐算法出错也不会污染结果。

**Q: 拼出来接缝处对不齐。**

两个来源：① 原图切分时不是严格的等分网格；② 各幅扫描时的缩放/裁切略有差异。

本工具按**每列取最大宽、每行取最大高**摆放，图幅小的那格会留白 ——
**宁可留白也不拉伸**，因为拉伸会累积变形，而留白至少位置是对的。

**Q: 能拼成 GeoTIFF 吗？**

现在输出的是 PNG/JPEG。若需要带"虚拟坐标"的 TIFF（每幅占据一个格子坐标，
可在 GIS 里打开但不代表真实经纬度），可以在 `assemble_by_layout.py` 基础上扩展 ——
说一声我加。
